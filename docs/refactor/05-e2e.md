## 2. Fixtures

`e2e/fixtures.ts`:
```ts
import { test as base, expect } from '@playwright/test';
import type { Role } from '../src/types/rbac';

type Fixtures = { loginAs: (role: Role) => Promise<void> };

export const test = base.extend<Fixtures>({
  loginAs: async ({ page }, use) => {
    await use(async (role) => {
      await page.goto('/login');
      await page.getByLabel('Tài khoản').fill('e2e-user');
      await page.getByLabel('Mật khẩu').fill('123456');
      // chọn role demo
      await page.getByRole('button', { name: ROLE_LABEL[role] }).click();
      await page.getByRole('button', { name: 'Đăng nhập' }).click();
      await expect(page).not.toHaveURL(/\/login$/);
    });
  },
});
export { expect };
```
> MSW db reset giữa các test: thêm handler dev-only `POST /api/__test__/reset` gọi `resetDb()`; fixture gọi nó trong `beforeEach`. Hoặc reload trang (nếu db không persist qua reload — thiết kế `db.ts` in-memory nên reload worker = reset).

`ROLE_LABEL` = map từ `src/constants/enums.ts` `ROLE_LABELS`.

## 3. Kịch bản

### 01-auth.spec.ts
- **Đăng nhập từng role → landing đúng**:
  | Role | URL sau login |
  |---|---|
  | ADMIN | `/thi-dua/dashboard-tong-quan` |
  | SPECIALIST | `/thi-dua/dashboard-tong-quan` |
  | LOCALITY | `/thi-dua/dia-phuong/trang-thai` |
  | BAN_LEADER | `/thi-dua/duyet/lanh-dao-ban/ban1` |
  | COUNCIL_CHAIR | `/thi-dua/duyet/hoi-dong-tdkt` |
  | STANDING_COMMITTEE | `/thi-dua/duyet/ban-thuong-truc` |
- Username/password rỗng → toast lỗi, ở lại `/login`.
- Vào route bảo vệ khi chưa login → redirect `/login`.
- Logout từ menu user → về `/login`; back button không vào lại được (token clear).

### 02-scoring.spec.ts (role SPECIALIST)
- Vào trang chấm theo tiêu chí, nhập điểm 3 tiêu chí cho 1 địa phương DRAFT.
- Tổng điểm cập nhật realtime.
- Nhập vượt max → tự clamp về max.
- Nút "Nộp" xuất hiện khi đủ tiêu chí (kể cả tổng 0 — nhập cả 3 ô = 0, nút vẫn hiện — B5).
- Click "Nộp" → toast "Đã nộp", badge đổi "Chờ duyệt Ban" (tiếng Việt — B1), ô nhập chuyển disabled.
- Reload trang → trạng thái giữ (đọc từ MSW).

### 03-approval-flow.spec.ts (luồng xuyên suốt)
Một test dài, nhiều role:
1. SPECIALIST: chấm + nộp địa phương X → `CHO_DUYET_BAN`.
2. `loginAs('BAN_LEADER')`: thấy X trong danh sách, "Duyệt" → X biến mất khỏi list Ban, toast.
3. `loginAs('COUNCIL_CHAIR')`: thấy X, "Duyệt" → chuyển BTT.
4. `loginAs('COUNCIL_VICE')` (xen giữa): nút "Duyệt" **disabled** (chỉ CHAIR).
5. `loginAs('STANDING_COMMITTEE')`: "Công bố" → `ConfirmDialog`, nhập sai keyword → nút disabled; nhập `CÔNG BỐ` → confirm → toast "Đã công bố".
6. `loginAs('LOCALITY')` (địa phương X): trang Kết quả hiện điểm + badge "Công bố", không có nút sửa.
7. Audit log của X: có đủ 4 mốc SCORE→APPROVE→APPROVE→PUBLISH, đúng người/vai trò.

### 04-reject-flow.spec.ts
- Từ `CHO_DUYET_BAN`: BAN_LEADER "Trả lại" không nhập lý do → nút disabled; nhập lý do → về `DRAFT`, SPECIALIST sửa lại được.
- Từ `CHO_DUYET_HOI_DONG`: CHAIR "Trả lại" → về `CHO_DUYET_BAN`.
- Từ `CHO_DUYET_BTT`: STANDING "Trả lại" → về `CHO_DUYET_HOI_DONG` (B4 — nhánh mới).
- Lý do trả lại hiển thị trong Audit timeline.

### 05-locality.spec.ts (role LOCALITY)
- Trang Trạng thái: hiện status đúng (submitted/processing/published) theo record.
- Trang Minh chứng: nộp file (mock: điền tên file) → xuất hiện trong danh sách; evidenceCount tăng.
- Xoá minh chứng khi record còn editable → được; khi `DA_CONG_BO` → nút disabled/ẩn.
- Trang Kết quả `/ket-qua/:nam`: breakdown điểm theo tiêu chí + lịch sử.

### 06-rbac.spec.ts
- SPECIALIST gõ URL `/thi-dua/admin/bang-tieu-chi` → redirect `defaultRouteForRole` (dashboard).
- LOCALITY gõ URL `/thi-dua/duyet/ban-thuong-truc` → redirect `/thi-dua/dia-phuong/trang-thai`.
- **LOCALITY gõ URL `/thi-dua/lich-su-thay-doi` → redirect `/thi-dua/dia-phuong/trang-thai`** (B14). Sidebar role LOCALITY KHÔNG có mục "Lịch sử thay đổi".
- **LOCALITY (dp1) thử xem địa phương khác**: gõ URL cổng có tham số địa phương khác (nếu còn) → không thấy dữ liệu dp2; hoặc trang chỉ hiển thị dp1 bất kể URL. Network: request `/api/scores?localityId=dp2` (nếu có) trả 403, UI hiện lỗi tải, không lộ số liệu.
- BAN_LEADER `ban1` không "Duyệt" được hồ sơ thuộc `ban2` (nút disabled) — nếu seed có 2 ban.
- Nav sidebar: mỗi role chỉ thấy menu item hợp lệ (ADMIN thấy "Bảng tiêu chí"+"Địa phương"; SPECIALIST thấy "Bảng chấm điểm"; LOCALITY KHÔNG thấy "Lịch sử thay đổi"; v.v.).

### 07-audit.spec.ts
- Trang Lịch sử thay đổi: lọc theo địa phương, thứ tự thời gian tăng dần, cột Người/Hành động/Giá trị cũ→mới đúng.
- Sau mỗi hành động ở test 03/04, audit thêm đúng 1 dòng.

## 4. Ổn định E2E

- Chờ bằng `expect(locator).toBeVisible()` / `toHaveURL`, không `waitForTimeout`.
- Toast Sonner: `page.getByText('Đã nộp', { exact: false })` rồi `.waitFor({ state: 'detached' })` nếu cần sạch trước bước sau.
- Mỗi spec độc lập: `beforeEach` reset db + login. Không dựa thứ tự chạy (trừ test-xuyên-suốt 03 cố tình gộp).
- `data-testid` chỉ thêm khi selector theo role/label không đủ (vd hàng bảng theo tên địa phương: `getByRole('row', { name: /Phường .../ })`).
